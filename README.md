# Semantic Search Platform

Hybrid keyword + vector retrieval over a 57k-passage financial QA corpus, with a
fine-tuned cross-encoder re-ranker on top, served through FastAPI.

Every number below is measured on the FiQA-2018 test set (648 queries with human
relevance judgements) and regenerated by `uv run python -m eval.score`.

## Results

| config | nDCG@10 | MRR@10 |
|---|---|---|
| Keyword only (BM25 / SQLite FTS5) | 0.2342 | 0.2905 |
| Vector only (all-MiniLM-L6-v2 / Chroma) | 0.3642 | 0.4406 |
| Hybrid, equal-weight RRF | 0.3475 | 0.4221 |
| Hybrid, weighted RRF | **0.3722** | **0.4505** |
| Hybrid + cross-encoder re-ranker | _pending_ | _pending_ |

Published BEIR results put BM25 on FiQA at nDCG@10 ≈ 0.236. This implementation
measures 0.2342, which is a useful check that the retrieval and the scoring are
both wired correctly.

### The equal-weight fusion result

Equal-weight RRF scored **0.3475 — worse than vector search alone**. RRF treats
every input ranking as equally trustworthy, and on this corpus BM25 is
substantially weaker than the dense retriever, so fusing them 1:1 pulled good
vector hits down the list.

Adding a per-ranking weight fixed it. The weight was tuned on the **validation**
split (500 queries), sweeping 0.05 to 0.20 and selecting 0.1; the test set was
measured once, afterwards. The test set never influenced the weight.

## Architecture

```
query
  ├─ SQLite FTS5  ──── BM25 ranking ────┐
  │                                     ├─ weighted RRF ─→ top 50
  └─ Chroma       ──── cosine ranking ──┘                    │
                                                             ▼
                                              cross-encoder re-ranker
                                                             │
                                                             ▼
                                                          top 10
```

### Why each layer exists

**Keyword (BM25 over SQLite FTS5).** Exact lexical matching for tickers, product
names, and jargon, where a dense embedding will happily return something
semantically adjacent but factually wrong. FTS5 gives BM25 for free inside a file
that requires no server.

**Vector (all-MiniLM-L6-v2 over Chroma).** Matches on meaning rather than
spelling, which is what FiQA's natural-language questions need — "how do I reduce
capital gains tax" shares almost no vocabulary with a good answer. This is the
single biggest win in the table, +55% over BM25.

**Weighted Reciprocal Rank Fusion.** BM25 scores and cosine similarities live on
incompatible scales, so blending the raw numbers is meaningless. RRF uses only
rank position. The per-retriever weight exists because equal weighting measurably
hurt — see above.

**Cross-encoder re-ranker.** The bi-encoder must compress each passage into a
vector before it ever sees the query. A cross-encoder reads the query and the
passage together, so attention runs across both. That is far more accurate and
roughly 100× slower per pair, which is exactly why it only ever scores the top 50
candidates rather than the whole corpus.

### Training the re-ranker

The re-ranker starts from `cross-encoder/ms-marco-MiniLM-L-6-v2` and is
fine-tuned on FiQA with **hard negatives mined from this project's own hybrid
retriever**: for each training query, the top 50 hybrid results minus the known
positives. Random negatives are trivially separable and teach the model nothing;
the useful signal is in passages the retriever already ranks as plausible.

```
5,500 training queries
52,666 training pairs
14,166 positives, 38,500 hard negatives
2.58 positives and 7 negatives per query
```

Mined pairs are cached to `data/train_examples.json`, so re-running training does
not repeat the ~15 minute mining pass.

## Running it

```bash
uv sync

uv run python -m index.keyword      # BM25 index, ~seconds
uv run python -m index.vector       # embed 57,638 passages, ~70s on MPS
uv run python -m rerank.train       # mine hard negatives, then fine-tune
uv run python -m eval.score         # regenerate the results table
uv run uvicorn api.app:app --reload
```

Everything runs locally on Apple Silicon; sentence-transformers selects the MPS
backend automatically and falls back to CPU.

## API

`POST /search`

```json
{ "query": "how do i reduce capital gains tax", "top_k": 5, "mode": "hybrid" }
```

`mode` is one of `keyword`, `vector`, `hybrid`, `rerank`, which makes every row
of the results table reproducible live — you can watch the re-ranker reorder
results against plain hybrid on the same query.

**`score` is not comparable across modes.** It is BM25 for `keyword`, cosine
similarity for `vector`, the RRF score (~0.03) for `hybrid`, and a raw
cross-encoder logit for `rerank`. Ranks are comparable; scores are not.

`GET /health` returns `{"status": "ok"}`.

If no trained checkpoint exists, the API still starts and every mode except
`rerank` works; `rerank` returns 503 with instructions.

## Stack

Python 3.12, UV, sentence-transformers (embeddings + CrossEncoder), Chroma,
SQLite FTS5, FastAPI + Pydantic, pytrec_eval, pytest.

Metrics come from `pytrec_eval` (bindings to NIST's `trec_eval`) rather than a
hand-written implementation, so the numbers are the standard ones.

## What this is not

No Docker, no CI/CD, no auth, no frontend, no distributed serving. It is a
demonstration of the retrieval and re-ranking stack, sized to be read in one
sitting.
